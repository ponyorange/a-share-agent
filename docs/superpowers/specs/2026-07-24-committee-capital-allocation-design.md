# 投委会定额资金次日组合设计

## 目标

让用户以一笔独立模拟资金（首个明确场景为 5000 元）发起投委会。系统从沪深主板股票和场内 ETF 中筛选标的，给出最多 3 只、可按真实交易单位执行的模拟买入组合，并展示：

- 买入标的；
- 参考买价；
- 买入股数或份额；
- 预计占用资金和剩余现金；
- 经历史校准的下一交易日上涨概率；
- 预期下一交易日涨幅及收益区间；
- 数据质量、主要风险和不买理由。

系统允许全部持有现金。没有合格信号时不得为了填满资金而强行推荐，也不得把 LLM 的主观 `confidence` 当作上涨概率。

本功能提供模拟决策支持，不承诺收益，不自动执行真实交易。

## 已确认的产品决策

- 资金是独立模拟组合，不读取或影响现有持仓。
- 候选范围为沪深主板股票与场内 ETF 混合池。
- 预测周期为下一交易日。
- 优先优化上涨概率，再比较扣除预计交易成本后的预期涨幅。
- “可买”要求校准上涨概率不低于 60%。
- 最多推荐 3 只标的。
- 允许空仓并保留全部 5000 元现金。
- 权威概率和预期收益由确定性量化模块产生；投委会负责解释、质疑和否决，不得篡改数值。

## 范围定义

### 沪深主板股票

股票池仅包括沪市、深市主板及原中小板并入主板后的标的。排除：

- 创业板、科创板和北交所；
- ST、退市整理和已退市标的；
- 停牌或当前不可交易标的；
- 上市时间不足以形成最低校准样本的标的；
- 流动性不达标的标的；
- 以当前资金无法买入至少一手的标的。

现有 `hs` 分类包含创业板，不能直接作为本功能的严格主板定义。实现时应新增明确的主板筛选规则，避免改变其他页面对 `hs` 的既有语义。

### 场内 ETF

包括可正常交易且历史数据充足的股票型、宽基、行业和主题 ETF。排除货币类、流动性不足、停牌、数据不足或当前不可交易的 ETF。

### 非目标

首版不包括：

- 创业板、科创板、北交所、港股和美股；
- 盘中择时和分钟级预测；
- 机器学习训练平台；
- 自动实盘下单；
- 用户自定义复杂约束；
- 对明日上涨或收益作确定性保证。

## 总体架构

采用“确定性量化引擎 + 投委会复核”的混合架构。

```text
会议输入
  -> 候选池粗筛
  -> 精确行情冻结
  -> 次日预测与历史校准
  -> 合格候选集
  -> 投委会分析、辩论与风控
  -> 整手资金分配
  -> 主席确认
  -> 最终模拟组合
```

量化模块是概率、预期收益和资金分配的权威来源。LLM 角色可以引用数据、指出风险或建议否决，但不能生成不存在的概率，也不能直接修改权威数值。主席结论必须引用最终分配产物并保持一致。

## 会议输入

创建会议请求增加：

```text
capital_amount
portfolio_mode = standalone
asset_scope = mainboard_and_etf
horizon = next_day
max_positions = 3
minimum_up_probability = 0.60
```

约束：

- `capital_amount` 必须为有限正数，并使用十进制定点金额处理；
- 首版 UI 默认 5000 元，但后端不能写死；
- 输入参数随会议冻结并参与请求幂等哈希；
- 重试和重放必须使用同一组冻结输入。

## 候选筛选与数据冻结

### 两阶段筛选

第一阶段只使用实时行情快照做低成本粗筛：

- 板块和资产类型合法；
- 非 ST、非停牌、非退市整理；
- 日均成交额和当前流动性达标；
- 最新价格有效；
- 资金至少能买一手；
- 粗略动量、量比、换手率和成交额评分。

第二阶段最多对粗筛后的 30 个混合候选拉取完整日线和必要的市场数据，计算精确特征。不得再对 `hs` 大池的约 250 只标的逐只采集日线。

### 单标的故障隔离

单只标的数据源失败时：

1. 记录标的、数据源、错误类别和重试结果；
2. 将该标的标为不可用并跳过；
3. 继续处理其他候选；
4. 由数据助手在群聊中汇报降级数量。

仅在以下情况终止会议：

- 合格候选为空；
- 关键市场级数据整体不可用；
- 数据失败比例超过配置阈值；
- 剩余样本不足以产生可信预测。

失败时应发送数据助手的 `failed` 消息，并明确说明原因。不得再用主席身份展示 `UNKNOWN / hold / 0%` 作为数据采集错误的替代。

## 次日预测模型

### 预测口径

- 标签：下一交易日收盘价相对当前交易日收盘价是否上涨；
- 次日收益：`next_close / current_close - 1`；
- 预期涨幅与上涨概率使用同一预测窗口；
- 股票和 ETF 分开建模、分开校准。

### 特征

首版复用并扩展现有确定性因子，包括：

- 1、5、10、20 日动量；
- 相对沪深 300 强弱；
- 均线位置和趋势；
- 成交量、量比和成交额变化；
- 近期波动率和下行波动；
- 市场状态；
- 资产类型和必要的流动性特征。

新闻、基本面和 LLM 观点可作为投委会解释证据，但首版不直接进入权威概率，避免不可重放输入污染历史校准。

### 时间滚动验证

历史验证必须遵循时间顺序。每个历史预测时点只能使用当时已经可见的数据：

- 特征不得引用未来 K 线；
- 校准器不得使用验证日期之后的数据；
- 训练、校准和验证窗口按交易日滚动；
- 股票和 ETF 的样本、阈值及结果分别统计。

测试必须包含显式的数据泄漏断言。

### 概率校准与预期收益

原始因子分数先产生排序信号，再通过历史滚动样本校准为上涨概率。首版固定采用五分位分箱、Beta-Binomial 平滑和单调池相邻违背者算法（PAVA）：按资产类型把滚动校准样本分为 5 个信号区间，以平滑后的区间上涨频率作为概率，再强制概率随信号单调不降。不得直接把模型 `confidence`、原始因子分数或历史总体胜率展示为个股上涨概率。

预期收益使用相似信号样本的去极值均值与中位数估计，并输出分位区间。每个预测结果至少包含：

```text
symbol
asset_type
as_of
up_probability
expected_return
return_interval
sample_count
historical_hit_rate
calibration_version
data_quality
evidence_ids
```

候选只有同时满足以下条件才能进入资金分配：

- `up_probability >= 0.60`；
- 扣除预计交易成本后的 `expected_return > 0`；
- 校准样本数达到配置下限；
- 数据质量合格；
- 未命中硬风控。

## 投委会职责

各角色使用冻结预测产物开展讨论：

- 数据助手：说明候选数量、数据时间、跳过标的和降级情况；
- 技术、量化、基本面和新闻分析师：从各自角度解释或质疑候选；
- 多空辩手：围绕候选的上涨概率、收益区间与风险提出支持和反对意见；
- 交易员：从合格候选中提出组合意向，不自行计算股数；
- 回测员：检查校准版本、样本量、命中率和时间滚动结果；
- 风控官：执行硬风控并可否决候选或整个组合；
- 主席：确认权威分配结果，或输出全现金结论。

LLM 输出中的 `confidence` 只表示角色对自己观点的确信程度，UI 必须与 `up_probability` 明确区分。

## 定额资金分配

### 交易单位

- A 股主板股票买入按 100 股整数倍；
- 普通场内 ETF 买入按 100 份整数倍；
- 价格和金额采用十进制定点计算；
- 不允许用小数股、小数份额或目标权重掩盖不可成交数量。

### 费用与现金缓冲

费用模型可配置，至少包含：

- 买入佣金率；
- 最低佣金；
- 其他必要费用；
- 价格波动缓冲。

默认最多使用资金的 95%，至少保留 5% 现金。结果必须展示预计费用和剩余现金。卖出相关费用只用于收益评估，不在本次买入占款中重复扣除。

### 分配目标与约束

分配采用按优先级排序的确定性整数优化：

1. 只选择上涨概率达到 60% 的候选；
2. 优先提高组合中标的的校准上涨概率；
3. 在概率接近时提高扣费后预期收益；
4. 最多 3 只；
5. 单只股票最多占初始资金 60%；
6. 单只 ETF 最多占初始资金 70%；
7. 总预计占款不超过可投资金额；
8. 所有数量满足交易单位约束。

如果某标的一手金额超过其单标的上限，则跳过。若无可行组合，输出全现金计划，而不是放宽概率或交易约束。

权威分配结果至少包含：

```text
capital_amount
invested_amount
estimated_fees
cash_remaining
positions[]
  symbol
  name
  asset_type
  reference_price
  quantity
  lot_size
  estimated_amount
  portfolio_weight
  up_probability
  expected_return
  return_interval
  evidence_ids
reason_if_all_cash
```

## 数据产物与一致性

新增权威产物：

- `forecast_candidates`：精筛候选、校准概率、预期收益和数据质量；
- `allocation_plan`：满足交易单位和资金约束的最终模拟组合。

现有 `trade_proposals` 可继续作为投委会提案，但最终建议必须绑定 `allocation_plan`。最终产物哈希应覆盖冻结输入、预测版本、参考价格、费用模型、数量和现金余额，保证审批、重放与展示一致。

任何最终消息或结果卡中的概率、涨幅、数量和金额都必须来自权威产物，不能从聊天文本反向解析。

### 与现有决策模型的衔接

现状基线：

- 创建会议只有 `symbols` / `boards`，没有资金输入；现金来自模拟盘账户快照。
- `trade_proposals` 支持多标的，但只有 `target_weight`，没有数量、预期收益或上涨概率。
- `FinalDecision` 顶层 `symbol` / `action` / `target_weight` 只摘要首条提案；主席通过时还与首条提案硬锁定。
- 股数在回测/审批阶段由 `weight × equity / price` 推算，再按 100 整手取整。

定额资金模式下必须改成：

1. `portfolio_mode=standalone` 时，使用会议输入的 `capital_amount` 作为独立模拟资金，不读取现有持仓。
2. 权威仓位来自 `allocation_plan.positions[]`，不再把“首条 proposal 的 weight”当作最终仓位。
3. `FinalDecision` 增加对完整组合的引用：至少保存 `allocation_plan` 的哈希或 artifact 引用，以及 `positions` 摘要；顶层单标的字段仅作兼容展示，空仓时使用确定性占位（如 `action=hold`、`symbol=CASH`、`target_weight=0`），不得再使用 `UNKNOWN`。
4. 主席节点改为确认或否决整份 `allocation_plan`；若风控否决，则强制落到全现金计划，而不是把首条买入提案改成 hold 后仍保留其他未摘要仓位。
5. 独立资金首版仅提供模拟建议，不写入现有模拟盘账户；页面隐藏审批入口，审批 API 对该模式明确拒绝。未来若单独启用隔离账户执行，数量必须以 `allocation_plan` 的整手数量为准，不得从权重重算。

## 前端体验

### 发起会议

会议创建区增加：

- 模拟资金输入，默认 5000 元；
- 候选范围“沪深主板 + ETF”；
- 下一交易日预测说明；
- 风险提示。

### 会议过程

群聊保留现有角色流式体验，并新增：

- 数据助手汇报粗筛、精筛和降级进度；
- 量化/回测消息可展开概率校准证据；
- 数据失败时展示具体、可操作的失败原因。

### 最终组合卡

组合卡展示：

- 标的代码、名称和类型；
- 参考买价；
- 买入股数或 ETF 份额；
- 预计金额和组合占比；
- 上涨概率；
- 预期涨幅和收益区间；
- 主要风险；
- 预计费用和剩余现金；
- 数据截止时间和校准版本。

全现金结果应作为正常决策展示，不使用失败样式。页面固定标注“模拟建议，不构成收益保证或自动交易指令”。

## 错误处理

- 单标的行情失败：跳过、记录并继续；
- 校准样本不足：标记不可信，不进入分配；
- 最新价格无效：不生成数量；
- 一手金额超预算或仓位上限：跳过并说明；
- 无标的达到 60%：全现金；
- 组合预期收益扣费后不为正：全现金；
- 市场级关键数据不可用：会议失败，由数据助手说明；
- LLM 失败：保留确定性预测和分配结果，角色消息标记降级；
- 分配产物与主席文本不一致：拒绝完成并使用权威产物生成确定性摘要。

## 可配置项

建议新增独立配置段，避免复用现有推荐列表的大池参数：

```yaml
committee:
  capital_allocation:
    max_precise_candidates: 30
    max_positions: 3
    minimum_up_probability: 0.60
    max_stock_weight: 0.60
    max_etf_weight: 0.70
    cash_reserve_ratio: 0.05
    minimum_calibration_samples: 40
    max_symbol_failure_ratio: 0.30
    stock_lot_size: 100
    etf_lot_size: 100
```

费用模型应单独配置，并在结果中记录实际使用的配置版本。

## 测试与验收

### 单元测试

- 严格主板分类排除创业板、科创板和北交所；
- 5000 元至少一手可买性筛选；
- 股票与 ETF 分开校准；
- 时间滚动验证无未来数据；
- 60% 门槛和扣费后正收益门槛；
- 100 股/份整数倍约束；
- 最多 3 只；
- 单标的仓位上限；
- 最低佣金和现金缓冲；
- 无可行组合时全现金；
- 单标的数据失败不终止整个快照。

### 集成测试

- 创建请求冻结资金和策略参数；
- 同一冻结输入与版本可重放出相同权威产物；
- `forecast_candidates`、`allocation_plan` 与最终决策一致；
- 主席无法篡改权威概率或数量；
- 市场级失败产生数据助手失败消息；
- LLM 降级时仍可展示确定性结果。

### 端到端验收

以 5000 元、沪深主板 + ETF、下一交易日为输入：

1. 页面显示候选筛选和数据进度；
2. 单只日线采集失败不会中止会议；
3. 聊天角色引用同一组冻结概率；
4. 最终最多展示 3 只；
5. 每只数量为 100 的整数倍；
6. 总占款、费用和剩余现金计算一致；
7. 低于 60% 时正常展示全现金；
8. 刷新后结果、证据和聊天可完整回放。

## 成功标准

- 用户能直接回答“5000 元可以买什么、买多少、预计占用多少钱、剩多少现金”；
- “明日上涨概率”和“预期涨幅”都有历史校准证据，不来自 LLM 主观置信度；
- 不再因整板中单只股票采集失败而终止会议；
- 所有推荐数量满足真实交易单位和资金约束；
- 没有可信机会时系统明确建议空仓；
- 同一冻结输入和版本的结果可审计、可重放。
