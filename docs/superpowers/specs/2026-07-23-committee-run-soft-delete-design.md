# 投委会会议记录软删除设计

## 目标

允许用户从投委会工作台删除当前选中的历史会议记录，同时保留完整审计数据。第一版仅支持单条删除，不支持批量删除或恢复入口。

## 行为约束

- 仅 `completed`、`failed`、`cancelled` 终态会议可删除。
- `queued`、`running` 及其他处理中状态删除时返回 HTTP 409，不自动取消会议。
- 用户只能删除自己的会议。
- 删除采用软删除：会议文档写入 `deleted_at` 和 `deleted_by`，不删除事件、产物、Redis checkpoint、审批或模拟交易数据。
- 已删除会议不再出现在普通列表中，普通详情查询按不存在返回 404。
- 对已删除会议再次删除按不存在返回 404。
- 删除历史会议不会撤销或改变已经产生的审批、订单和模拟交易。

## 后端设计

### 数据模型

`CommitteeRun` 增加可选字段：

- `deleted_at`: 带时区的 UTC 时间。
- `deleted_by`: 执行删除的用户 ID。

未删除记录两个字段均为空。仓储层负责保证二者同时写入。

### 仓储

增加 `soft_delete_run(user_id, run_id, now)`：

1. 按 `user_id + run_id + deleted_at 不存在` 查找记录。
2. 若不存在，抛出 `RunNotFound`。
3. 若状态不是允许删除的终态，抛出 `IllegalStatusTransition`。
4. 使用当前版本和未删除条件执行原子更新，写入删除字段并递增版本。
5. 并发更新失败时重新读取并返回明确的不存在、非法状态或版本冲突错误。

`get_run` 和 `list_runs` 默认加入未删除过滤条件。后台任务只处理活跃状态，因此不新增包含已删除记录的公共查询入口。

### HTTP API

新增：

`DELETE /api/advisor/committee/runs/{run_id}`

成功返回 HTTP 200：

```json
{
  "run_id": "…",
  "deleted": true
}
```

错误映射：

- 404：记录不存在、已删除或不属于当前用户。
- 409：会议尚未进入终态，或发生并发状态变化。

接口不删除 Redis 数据或 Mongo 关联集合，确保审计链仍可由管理员离线追溯。

## 前端设计

- 在当前会议详情的操作区增加“删除记录”按钮，仅终态会议显示。
- 点击后显示原生确认框，文案明确说明“只会从历史列表隐藏，不会撤销审批或订单”。
- 用户确认后调用删除接口，并禁用其他会议操作。
- 成功后：
  1. 中止当前详情、动作和 SSE 请求。
  2. 清空当前选中详情及时间线。
  3. 刷新历史列表。
  4. 自动选中刷新结果中的第一条记录；若列表为空则显示空状态。
- 失败时保留当前详情，并在页面警告区显示后端错误。

## 测试

后端测试：

- 终态记录可以软删除，删除字段和版本正确更新。
- 活跃记录删除返回 409，数据不变。
- 其他用户删除返回 404。
- 已删除记录从列表中消失，详情返回 404。
- 重复删除返回 404。
- 关联事件和产物仍保留。

前端测试：

- 仅终态详情显示删除按钮。
- 取消确认时不调用 API。
- 确认后调用正确的 DELETE 接口。
- 删除成功后刷新列表并选择下一条；无剩余记录时显示空状态。
- 删除失败时保留当前记录并显示错误。

## 非目标

- 批量删除。
- 删除恢复界面。
- 物理清理事件、产物、checkpoint、审批或订单。
- 自动取消并删除进行中的会议。
