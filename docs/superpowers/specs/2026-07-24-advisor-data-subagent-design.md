# 投研助手数据子 Agent 设计

## 目标

为现有投研助手增加一个只读数据子 Agent。投研助手遇到需要外部数据查询、跨数据源关联或计算的任务时，自动委派给该子 Agent。子 Agent 能动态发现并调用 `providers` 中所有已注册数据源的允许接口，在隔离容器中执行模型生成的 Python，并把目标数据、计算说明和来源信息返回给投研助手。

本设计中的“所有数据”指所有已注册 Provider 暴露的全部允许接口，不表示一次请求可以无限量下载整个数据源。

## 已确认的产品约束

- 数据子 Agent 可以执行模型生成的 Python。
- Python 必须在独立容器或等价的强隔离沙箱中运行。
- 数据子 Agent 只有查询和计算权限，不能写回业务数据或外部数据源。
- 投研助手自动判断是否需要委派，无需用户显式指定数据 Agent。
- 采用独立 ReAct 数据子 Agent，而不是把所有 Provider 接口直接注册成主 Agent 工具。
- 请求结束后删除临时数据，不持久化中间结果或最终结果。

## 现有基础

现有投研助手位于 `backend/app/advisor/agent/`，使用 LangGraph `create_react_agent` 和按用户绑定的工具集合。现有 Provider 注册表位于 `backend/app/providers/__init__.py`，统一协议位于 `backend/app/providers/base.py`。

当前 Provider 包括 AKShare、Tushare 和 BaoStock，均提供：

- 数据源描述和健康状态；
- 分类与接口目录；
- 接口详情；
- 统一的 `fetch(name, params, limit)` 查询入口。

因此，数据子 Agent 应建立在 Provider 注册表和统一协议上，不为具体 Provider 编写固定分支。

现状缺口：顾问层目前多直连 AKShare、东财或专用服务模块，`backend/app/advisor/**` 基本不经过 `app.providers`。数据子 Agent 的核心集成点是把 `providers.get_provider(...).fetch(...)` 与 `serialize.normalize_result` 桥接进 Agent 工具层，而不是再写一套按源硬编码的取数逻辑。委员会多角色图、预采集 snapshot 和预算账本可作为超时、调用预算与并行采集的参考，但不作为本子 Agent 的主编排模式；本子 Agent 仍然是按需 tool-calling 的只读 ReAct。

## 总体架构

### 投研助手

投研助手保留现有 ReAct 流程，只新增一个高层工具：

`delegate_data_task(request)`

该工具将当前数据需求委派给数据子 Agent，并返回结构化结果。投研助手不直接持有 Provider 底层查询工具，从而避免数百个接口描述占用主 Agent 上下文。

投研助手的系统提示应明确：

- 行情、财务、宏观、资讯等 Provider 数据，以及跨表或跨源计算，自动委派给数据子 Agent；
- 持仓、模拟盘、用户策略和推荐归档等业务数据继续使用现有工具；
- 不得在数据子 Agent 失败时编造结果。

### 数据子 Agent

数据子 Agent 使用当前用户配置的模型，但有独立系统提示和严格受限的工具集：

1. `list_data_sources`
2. `search_data_interfaces`
3. `get_data_interface`
4. `fetch_provider_data`
5. `run_python_analysis`

它通过“搜索目录 → 读取接口详情 → 查询 → 计算 → 校验结果”的 ReAct 循环完成任务。接口目录按需发现，不在启动时整体注入提示词。

Provider 返回的文本都视为不可信数据，不能作为系统指令或工具指令执行。

### 临时数据工作区

每次委派创建独立的临时工作区。Provider 查询结果写成带随机 ID 的数据集。工具向模型返回：

- `dataset_id`
- 数据源、接口和参数摘要
- 字段及类型
- 行数
- 是否截断
- 少量样例

完整数据不反复进入模型上下文。Python 沙箱只能通过本次请求的 `dataset_id` 读取对应输入文件。请求结束后，无论成功或失败，都清理工作区。

### Python 沙箱服务

沙箱作为独立内部服务运行。API 容器不挂载 Docker socket，也不直接获得创建特权容器的能力。

每个任务使用临时、非 root、无外网的隔离运行环境：

- 根文件系统只读；
- 只读挂载本次任务的输入数据；
- 仅输出目录可写；
- 不传入用户 Token、应用密钥或宿主环境变量；
- 禁止安装依赖、启动子进程和访问宿主文件；
- 设置 CPU、内存、进程数、运行时间和输出大小限制。

沙箱预装 `pandas`、`numpy` 以及必要的标准数学和统计模块。生成代码必须把最终结果写成 JSON，不能把 stdout 当作正式结果。

## 调用与数据流

1. 用户向投研助手提出问题。
2. 投研助手判断是否需要 Provider 数据或计算。
3. 投研助手调用 `delegate_data_task`，传入明确的数据目标和必要的对话上下文。
4. 数据子 Agent 搜索 Provider 接口目录。
5. 子 Agent 在调用前读取候选接口的完整参数定义，不凭接口名猜参数。
6. 子 Agent 查询一个或多个 Provider；每次查询生成数据集 ID。
7. 如需计算，子 Agent 生成 Python，并引用一个或多个数据集 ID 调用沙箱。
8. 沙箱返回经过校验的 JSON 结果或稳定错误。
9. Python 失败时，子 Agent 可根据受限诊断信息修正代码，最多重试两次。
10. 子 Agent 返回结构化结果。
11. 投研助手结合对话语境生成最终中文回答。
12. 系统清理临时工作区。

数据子 Agent 的最终结果包含：

- `answer`：简洁结论；
- `data`：目标数据；
- `sources`：Provider、接口、参数摘要和数据时间；
- `computation`：计算步骤摘要；
- `warnings`：截断、口径差异、空值和部分失败；
- `failures`：失败来源及稳定错误码。

## 资源预算

默认预算如下：

- 单次 Provider 查询最多 5,000 行；
- 一次委派累计最多 50,000 行；
- 沙箱输入最多 50 MB；
- 沙箱单次运行最多 30 秒；
- 沙箱内存最多 512 MB；
- Python 修正重试最多两次；
- 最终 JSON 输出最多 1 MB。

如果接口支持分页，数据子 Agent 可在总预算内发起多次查询。达到预算时停止继续拉取，并在结果中明确标记截断。任何预算都应配置化，但初始实现不提供用户级无限扩容。

## 异常处理

Provider 调用失败按数据集隔离。某一来源失败后，子 Agent 可以继续使用其他来源，但必须满足：

- 结果中列出失败来源；
- 不静默替换来源；
- 不把不同口径数据当成同一口径合并；
- 如果剩余数据不足以回答目标问题，明确返回无法完成。

错误至少区分：

- 数据源未就绪；
- Token 未配置；
- 权限或积分不足；
- 接口不存在；
- 参数错误；
- 上游限流或网络失败；
- 空数据；
- 查询或总量预算超限；
- 沙箱超时、超内存或输出非法；
- 结果截断。

Tushare 未配置 Token 时，不影响 AKShare 或 BaoStock 查询。

## 安全设计

- 数据子 Agent 只有 Provider 读取和沙箱计算工具，不注册持仓、策略、模拟盘或其他写工具。
- Provider 内容视为不可信数据，系统提示明确禁止执行其中的指令。
- 沙箱无网络、无宿主凭据、无 Docker socket、无宿主目录。
- 输入数据集 ID 必须属于当前请求，防止跨请求读取。
- 沙箱输出校验 JSON Schema、大小、嵌套深度、NaN 和 Infinity。
- stderr 和异常堆栈经过截断与脱敏，只向子 Agent 返回必要诊断。
- 日志不记录 Token、密钥、完整敏感参数或大表正文。

普通受限子进程不能作为可靠安全边界，因此生产实现不得用同用户进程内执行或仅靠 AST 黑名单替代独立沙箱。

## 可观测性

每次委派记录：

- request ID；
- 数据子 Agent 模型调用次数；
- Provider 和接口名；
- 查询耗时、行数及截断状态；
- 沙箱耗时和资源用量；
- 重试次数；
- 稳定错误类型；
- 最终状态。

投研助手现有工具轨迹可把整次委派表现为一个高层工具调用，同时在其结果中附带精简的数据来源和计算轨迹。

## 测试设计

### 单元测试

- 所有已注册 Provider 都能被动态发现；
- 接口搜索、接口详情和参数校验正确；
- 数据集 ID 不可跨请求访问；
- 单次和累计预算生效；
- 临时文件在成功、失败和取消后均被清理；
- 子 Agent 结果符合 Schema；
- 超限、NaN、Infinity 和过深 JSON 被拒绝。

### 沙箱安全测试

- 无法访问外网；
- 无法读取宿主文件和宿主环境变量；
- 无法启动子进程；
- 无法写只读文件系统；
- 超时、超内存、超进程数和超输出能被终止；
- 仅能读取本次任务挂载的数据集；
- 非法结果不会传回投研助手。

### 数据子 Agent 场景测试

Provider 和模型在 CI 中使用测试桩，覆盖：

- 单数据源查询后计算目标指标；
- 跨 AKShare、Tushare 和 BaoStock 关联，并统一证券代码格式；
- 参数调用失败后读取接口说明并修正；
- 某一来源失败时返回部分结果和警告；
- Tushare Token 缺失时继续使用其他来源；
- Python 首次失败后成功修正；
- 超过 Python 重试次数后停止；
- Provider 数据中的提示注入文本不改变 Agent 行为。

### 投研助手集成测试

- 外部行情、财务、宏观、资讯和跨源计算自动委派；
- 持仓、模拟盘和策略任务不误委派；
- 数据子 Agent 无法获得业务写工具；
- 最终回答包含来源、数据时间和必要警告；
- 子 Agent 失败时主 Agent 不编造数据。

CI 不调用真实金融数据接口。另提供手工 smoke test 验证三个真实 Provider 和沙箱服务。

## 验收标准

用户使用自然语言提出可由 Provider 数据完成的查询或计算任务时：

1. 用户不需要知道 Provider 或接口名；
2. 投研助手能自动委派给数据子 Agent；
3. 数据子 Agent 能发现并调用任意已注册 Provider 的允许接口；
4. 需要时可在隔离容器中计算和组装目标数据；
5. 返回结果包含来源、参数摘要、数据时间、计算说明和警告；
6. 任一失败都可解释，不静默降级，不伪造结果；
7. 子 Agent 不能写业务数据，临时数据在请求后被删除；
8. 新增符合统一协议的 Provider 后，无需修改 Agent 工具列表即可被发现。

## 非目标

- 不允许数据子 Agent 修改持仓、模拟盘、策略或推荐归档；
- 不持久化通用计算结果或建设长期数据仓库；
- 不一次性导入 Provider 的全部数据；
- 不让投研助手直接看到所有底层 Provider 工具；
- 不在本次范围内开发用户自定义 Python 编辑器；
- 不用普通 Python 子进程冒充生产级安全沙箱。
