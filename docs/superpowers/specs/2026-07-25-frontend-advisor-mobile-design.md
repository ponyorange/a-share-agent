# Frontend Advisor 移动端适配设计

## 目标

改善 `frontend-advisor` 在手机上的信息层级、数据可读性和聊天交互，重点解决：

- “今日关注”的归档元信息、筛选和批量操作堆叠混乱；
- 窄屏表格强制压缩，中文名称逐字换行；
- 模拟盘账户信息、收益指标、下单操作和多张表格过于拥挤；
- Agent 会话侧栏、快捷问题、消息区、输入框和浮动面板切换器争抢视口；
- 软键盘弹出或存在底部安全区时，聊天输入区错位或被遮挡。

适配在视口宽度不超过 `768px` 时启用，重点验证 `375–430px`。桌面布局和现有业务接口保持不变。

## 方案选择

采用混合响应式方案：

- 保留现有桌面表格和双栏聊天结构；
- 手机默认使用专用卡片布局；
- 数据密集页面保留“表格视图”，通过真实横向滚动展示完整列；
- 通用间距、按钮和表单通过 CSS 响应式规则适配；
- 不新增后端接口，不改变账户、推荐、订单或聊天数据协议。

不采用仅缩小字号和间距的轻量方案，因为无法解决表格逐字换行和聊天视口冲突。也不重写整个前端设计系统，避免扩大改动范围。

## 全局移动端框架

### 顶栏与导航

- 不超过 `768px` 时，品牌区保持单行，主导航变为紧凑的横向滚动区或菜单入口，不能撑成多行。
- Agent 聊天页使用专用紧凑顶栏，只保留会话菜单、当前会话标题和新对话入口。
- “基础 / Agent”面板切换在普通页面可保留底部入口，但必须预留安全区；在聊天页移入菜单，不得悬浮在输入框上。
- 页面水平内边距缩小，但所有主要触控目标保持至少约 `44px` 高。

### 通用数据视图

- 同一数据集在手机上提供 `card` 和 `table` 两种视图，默认 `card`。
- 用户切换的视图偏好存入本地存储，并按页面或数据集分别记录。
- 表格视图的表格元素设置内容驱动的最小宽度；外层容器负责横向滚动。
- 名称、代码和关键数字列禁止逐字断行；操作列保持完整触控区域。
- 卡片抽取相同数据源，不复制请求或业务计算逻辑。

### 安全区与滚动

- 底部固定或粘性操作区使用 `env(safe-area-inset-bottom)`。
- 页面只允许需要滚动的内容区滚动，避免 `100dvh` 容器与浏览器地址栏、软键盘产生双滚动。
- 支持 `prefers-reduced-motion`，不新增必须依赖动画才能理解的状态。

## 今日关注

### 首屏信息

- 标题旁展示推荐日和归档状态。
- 将“大池、精算、推荐”提升为三项紧凑指标。
- 数据源、筛选策略、错误数等长元信息收进“筛选与数据源”可展开区域。
- 板块筛选保持横向 chip；次要动作与主操作分组，不把六个以上控件塞进同一行。
- “一键买入 ETF / 沪深”作为明确主操作，可在内容底部粘性展示并避开安全区。

### 候选数据

- 手机默认展示候选卡片：名称、代码、收盘、涨跌幅、评分和主要操作。
- 卡片保留现有“诊断 / 查看 K 线”操作；板块级“一键买入 ETF/沪深”作为页面主操作，继续使用现有确认和业务校验，不新增单标的交易语义。
- 表格视图沿用现有列，但设置足够的最小宽度，并提示横向滑动。
- 空数据、加载中、刷新失败和部分数据错误继续使用现有状态组件，并在卡片/表格视图上方统一展示。

## 模拟盘

### 账户总览

- 首屏突出总权益和总收益；现金、市值作为二级指标。
- “历史收益”和“持仓收益”的细分项默认折叠，展开后展示总计、一键买入和手动买入拆分。
- 刷新市值保留在首屏；刷新过程显示进度，不能阻断页面其它只读内容。

### 操作分层

- 常用“下单”作为主操作，表单在手机上纵向排列，选择方向、代码、数量和提交按钮均占用清晰行。
- “一键卖出”和“重置资金”收进“更多操作”，继续使用现有二次确认。
- 删除持仓仍属于危险操作，不能与普通详情按钮使用同等视觉权重。

### 持仓、跟踪与成交记录

- 持仓默认卡片显示名称、代码、数量、成本、现价、市值和浮盈亏；卡片提供卖出和详情。
- 一键买入跟踪、成交记录也默认卡片展示，并保留分页。
- 三组数据均可切换至横滑表格；表格名称不换行，分页按钮扩大触控区域。
- 空状态、加载失败和分页失败不清空已加载的数据；状态信息显示在对应区块内。

## Agent 聊天

### 页面结构

- 手机端使用单栏全高布局，会话侧栏改为从左侧打开的抽屉。
- 顶栏显示菜单、当前会话标题和新对话入口；长标题省略，不挤压操作。
- 抽屉宽度约为视口的 `80–85%`，支持遮罩点击和关闭按钮退出。
- 桌面端继续使用现有会话侧栏与聊天主区双栏布局。

### 消息与快捷问题

- 消息气泡限制最大宽度，但允许助手消息在手机上占用更宽空间。
- Markdown 表格、代码块和长链接只在气泡内部横向滚动，不能撑宽整页。
- 快捷问题改为单行横向滚动，并提供“更多”入口；用户开始输入后弱化或收起。
- 工具调用和子 Agent 进度默认折叠；运行中可显示单行状态和进度，展开后查看详情。

### 输入区

- 输入区固定在聊天内容底部，并使用底部安全区；不能被“基础 / Agent”切换器覆盖。
- 文本框从约两行自动增长到最多约五行，之后内部滚动；关闭用户手动拉伸。
- 发送按钮保持固定触控尺寸和可见位置，不因输入框增高而换行。
- 软键盘弹出时，输入区保持在键盘上方，消息区缩短并继续可滚动。
- 生成中继续展示明确禁用/停止状态；错误消息显示在输入区附近但不覆盖最后一条消息。

## 组件边界

为避免把页面文件继续扩大，新增或抽取以下职责清晰的组件：

- `ResponsiveDataView`：管理卡片/表格视图切换和本地偏好，不负责请求数据；
- `RecommendationCard`：渲染单个候选标的及其现有操作；
- `PaperPositionCard`、`PaperTradeCard`：渲染模拟盘移动端记录；
- `MobileDisclosure`：承载长元信息和收益拆分；
- `AgentConversationDrawer`：只管理移动端会话抽屉展示与关闭；
- `AgentComposer`：统一文本增长、发送状态、键盘和安全区行为。

页面仍负责请求、状态组合和业务回调。桌面表格和移动卡片必须接收同一份数据与回调，避免逻辑分叉。

## 数据流与状态

1. 页面按现有 API 加载数据。
2. 页面将同一数据集合传入响应式数据视图。
3. CSS 媒体查询决定桌面默认表格或手机默认卡片；用户显式选择覆盖默认值。
4. 视图切换只改变展示状态，不触发重新请求。
5. 买入、卖出、删除、刷新和聊天发送继续调用现有处理函数。
6. 操作成功后按现有流程更新页面状态；两个视图同步反映结果。

本地存储读取失败时回退到默认视图；写入失败不阻断页面功能。

## 错误处理与可访问性

- 所有现有错误信息保留，新增折叠、抽屉和视图切换需提供可理解的文本标签。
- 抽屉打开后焦点进入抽屉，关闭后回到触发按钮；支持 Escape 关闭。
- 折叠区域使用原生 `details/summary` 或等价的 ARIA 属性。
- 视图切换使用按钮并暴露当前选中状态。
- 危险操作保持确认步骤，禁用状态不能仅依赖颜色表达。
- 涨跌颜色沿用现有语义，同时保留正负号和数值。

## 测试与验收

### 自动化测试

- 推荐页：手机默认卡片、切换表格、偏好恢复、卡片操作调用原回调。
- 模拟盘：指标折叠、持仓卡片、下单表单、危险操作入口、分页和表格切换。
- Agent：会话抽屉开关、快捷问题、composer 发送/禁用、工具进度折叠。
- 桌面回归：现有表格、双栏聊天和业务操作继续工作。
- 构建、lint 和现有 Vitest 全量测试通过。

### 视口验收

- 在 `375×667`、`390×844`、`430×932`、`768×1024` 验证主要页面。
- 页面不能出现非预期的整体横向滚动。
- 表格视图必须能横向滚动，名称不能逐字竖排。
- Agent 输入区在 iOS/Android 软键盘场景下可见，最后一条消息可滚动到输入区上方。
- 底部固定控件不与系统安全区或其它浮动控件重叠。
- 主要按钮、输入框和列表操作具备足够触控尺寸。

## 非目标

- 不改变后端 API、证券筛选规则、下单规则或 Agent 协议。
- 不重做桌面视觉风格。
- 不引入新的 CSS 框架或组件库。
- 不为投委会隐藏路由进行额外移动端重构；仅保证通用全局样式不破坏其现有布局。
